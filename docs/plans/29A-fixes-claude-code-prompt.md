# Claude Code prompt: 29A review fixes (before 29B)

Read first: `docs/plans/29A-completion-report.md`, `docs/plans/29A-billing-foundations-claude-code-prompt.md` (all hard rules still apply), and the files named below. An independent read-only review of the 29A working tree on 2026-10-24 found these problems. Fix each with a test that fails before the change. Do not start 29B.

1. **High, idempotency key reuse lets a client underpay.** `billing/wallet/wallet.go` Reserve (around 485-487) returns an existing hold for the key without checking its state, kind or amount; `quote.go` (around 433) relies on it. Sequence: create with key K (cost 10) fails the schedule guard, the hold is released, retry with K at capacity 20 and 13 days ahead (cost 48) with the correct `expected_cost` → the old released 10-credit hold is reused and captured. Fix: an existing hold for the key is reused only when `state = held` and kind, amount and price version match; otherwise return 409 `idempotency_key_reused` (new coded error, mapped through gRPC and HTTP, documented in `docs/api/billing.md`). Also make sure a retry after a failed create with the same key and the same body reserves a fresh hold rather than capturing a released one. Tests: same key, larger body after a failed create → 409 and nothing charged; same key, same body after a failed create → succeeds and charges once.
2. **Medium, "enforcement off writes nothing" is not true.** `quote.go` (around 311 and 322): with `credits.enforced` off, every create still creates a wallet row and, with the fingerprint adapter wired, grants welcome credits that start decaying before charging exists. Fix: when not enforced, the create path makes no billing writes (no wallet row, no welcome grant); the quote endpoint may still return `would_cost` without writing. Welcome credits are granted lazily once enforcement is on. Make `TestEnforcementOffWritesNoBillingRows` use the real fingerprint adapter and assert zero rows in `billing.wallets`, `credit_lots`, `ledger_entries`, `holds`, `welcome_grants`, `billing_outbox`. Also: if flags cannot load and nothing is cached, meetup creation must not fail when the last known state was "not enforced"; decide and document the fail mode (recommend: treat as not enforced, log and count).
3. **Low/Medium, the ledger can be truncated.** Migration 0026 trigger covers `UPDATE OR DELETE` only. Add `BEFORE TRUNCATE ... FOR EACH STATEMENT` (new migration 0028, with down), and change test cleanup to a method that does not need TRUNCATE on `ledger_entries` (for example a test-only role or dropping and recreating the test schema).
4. **Low, cancel before capture bypasses the refund cap.** `refunds.go` (around 106-111) and `plans.sql` (around 158): count `released`-for-refund outcomes toward the 3-per-30-days cap. Test it.
5. **Low, a full refund of a capture that went into debt still charges the debt.** `wallet.go` (around 738-782): on a full refund, write off the debt created by that hold's own capture before `settleDebt` runs. Test: capture with shortfall → full refund → balance and debt both back to before.
6. **Low, the flag email resolver ignores verification.** `cmd/monolith/wiring.go` `flagEmailResolver`: return the personal email only when it is verified. Test.
7. **Tidy:** split `billing/wallet/wallet.go` (851 lines) into `holds.go`, `capture.go`, `refunds.go`, `decay.go` with no behaviour change; full suite before and after.

Gates: `go vet ./...`, `gofmt`, `golangci-lint run ./...`, `go test -race ./...`, migrations up/down/up on a scratch database. Update `docs/plans/29A-completion-report.md` with a "Review fixes" section (each item, test name, result) and `docs/gap-tracker.md`.
